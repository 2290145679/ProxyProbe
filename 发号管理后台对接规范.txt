一、 系统概述与架构定位
--------------------------------------------------------------------------------
ProxyProbe 采用「非对称加密离线验签 + 毫秒级在线心跳打卡与吊销同步」的双轨混合安全架构。

1. 发号服务端职责：
   - 持有官方核心主私钥（必须高度保密），负责按套餐规格、机器码、有效期生成合法的商业许可证（License Key）。
   - 提供在线心跳核验接口，接收各客户端的心跳打卡，并返回当前许可证的状态（正常活跃或已被吊销）。
   - 提供许可证管理能力（生成、吊销、解吊销、列表查询）。

2. 客户端行为特征（对接参考）：
   - 客户端已预埋对应的「官方主公钥」，在没有网络时可依靠公钥独立验签。
   - 客户端后台守护线程每隔 30 秒会向发号中心发起一次心跳请求。
   - 当客户端在后台操作查询授权时，若距离上次心跳超过 20 秒，也会立即主动发起一次远程心跳。
   - 一旦发号中心返回 status == "revoked"，客户端立即执行 0 配额熔断，硬性拦截所有资源创建。

二、 密码学体系与密钥对规范
--------------------------------------------------------------------------------
1. 签名算法：Ed25519 (RFC 8032)
   - 签名输出长度固定为 64 字节（512 位）。
   - 私钥长度为 32 字节（256 位）。
   - 公钥长度为 32 字节（256 位）。

2. 官方主密钥对（当前客户端已预埋，新开发的发号后台必须沿用此密钥，否则已分发的客户端验签失败）：
   - 发号主私钥 (MASTER_PRIVATE_KEY_HEX):
     875cf2bcc0c92bb602eb6c150693ed1e308321f803b7cbf3674ec028ebea0ff3
   - 验签主公钥 (MASTER_PUBLIC_KEY_HEX):
     6637fdfd836e83fd31aa7c02698ab615d882bdb7533aaf2f83359480a1a5a4c3

3. 规范化 JSON 序列化要求（签名载荷预处理）：
   为了保证不同语言/环境计算出的摘要完全一致，在对载荷（Payload）计算签名之前，必须进行紧凑无空格排序序列化：
   - 键按字母顺序排序（sort_keys = True）
   - 分隔符无多余空格（separators = (',', ':')）
   - UTF-8 编码为原始字节流

四、 许可证字符串（License Key）结构与生成算法
--------------------------------------------------------------------------------
1. 完整许可证字符串格式：
   PPLIC-<URLSafe_Base64_Payload>.<URLSafe_Base64_Signature>

   - 固定前缀: "PPLIC-"
   - 第一部分: 载荷 JSON 的 URL-Safe Base64 编码（末尾的 "=" 填充符需去除）
   - 中间分隔: "."
   - 第二部分: 64 字节 Ed25519 签名的 URL-Safe Base64 编码（末尾的 "=" 需去除）

2. 载荷（Payload）字典字段定义：
   {
       "id": "LIC-202609-1A2B3C4D",       // 许可证唯一编号，格式: LIC-YYYYMM-8位随机HEX
       "type": "planet",                  // 套餐标识: stardust / planet / star / galaxy / universe
       "customer": "VIP客户张三",          // 客户名称/备注标识
       "machine_id": "PP-A1B2-C3D4-E5F6", // 绑定的机器码。若填 "ANY" 则表示不限制机器码
       "max_servers": 5,                  // 最大允许管理的服务器数量 (int)
       "max_nodes": 12,                   // 最大允许创建的代理节点数量 (int)
       "max_users": 12,                   // 最大允许创建的客户端用户数量 (int)
       "issued_at": 1727100000,           // 签发时的时间戳 (秒, int)
       "expire_at": 1758636000            // 到期时间戳 (秒, int)。填 0 表示永久买断
   }

3. 生成算法步骤伪代码：
   step 1: payload_bytes = JSON_Serialize(payload, sort_keys=True, separators=(',', ':')).encode('utf-8')
   step 2: signature_bytes = Ed25519_Sign(private_key_bytes, payload_bytes)
   step 3: payload_b64 = Base64_URLSafe_Encode(payload_bytes).rstrip('=')
   step 4: sig_b64 = Base64_URLSafe_Encode(signature_bytes).rstrip('=')
   step 5: license_key = "PPLIC-" + payload_b64 + "." + sig_b64

五、 核心 HTTP API 接口规范
--------------------------------------------------------------------------------
基础要求：
- 默认监听端口可配置（如 18888 或通过反向代理绑定标准 443/80）。
- 所有接口输入输出均采用 JSON 格式（Content-Type: application/json; charset=utf-8）。
- 支持跨域（CORS），响应需包含标准 CORS 响应头：
  Access-Control-Allow-Origin: *
  Access-Control-Allow-Headers: Content-Type
  Access-Control-Allow-Methods: GET, POST, OPTIONS

--------------------------------------------------------------------------------
5.1 客户端在线心跳与吊销核验接口【最核心接口】
--------------------------------------------------------------------------------
- 请求路径: POST /api/v1/license/ping
- 说明: 客户端每 30 秒轮询打卡，或客户端管理员打开后台时触发。发号中心在此记录客户端在线状态并下发吊销阻断。

- 请求参数 (JSON):
  {
      "license_key": "PPLIC-...",              // 客户端当前使用的许可证字符串 (必填)
      "machine_id": "PP-A1B2-C3D4-E5F6",       // 客户端本机的机器识别码 (必填)
      "version": "2.0.0",                      // 客户端内核版本号 (可选)
      "timestamp": 1727100000                  // 客户端当前时间戳 (秒)
  }

- 服务端处理逻辑:
  1. 校验 license_key 是否存在。若为空返回 400 {"status": "invalid", "message": "缺失许可证"}。
  2. 根据 license_key 查询数据库中的记录；若未查到，尝试根据 machine_id 查询。
  3. 若数据库中存在该记录：
     - 更新该记录的 last_ping_at = 当前时间戳，last_ping_ip = 客户端IP。
     - 若该记录的 status 字段为 "revoked"：
       立即返回 HTTP 200:
       {
           "status": "revoked",
           "message": "许可证已被吊销"
       }
  4. 若状态正常（active），返回 HTTP 200:
     {
         "status": "ok",
         "timestamp": 1727100000
     }

--------------------------------------------------------------------------------
5.2 签发新许可证接口
--------------------------------------------------------------------------------
- 请求路径: POST /api/v1/license/generate
- 请求参数 (JSON):
  {
      "customer": "客户名称或备注",            // 默认可填 "VIP客户"
      "machine_id": "PP-A1B2-C3D4-E5F6",       // 目标主机的机器码，不可为空。填 "ANY" 则不锁机器
      "plan_type": "planet",                   // 套餐代码: stardust / planet / star / galaxy / universe
      "days": 365                              // 有效天数。填 0 表示永久买断
  }

- 服务端处理逻辑:
  1. 读取对应 plan_type 的配额（max_servers, max_nodes, max_users）。
  2. 计算 expire_at（当前时间戳 + days * 86400，若 days==0 则 expire_at=0）。
  3. 生成 ID: LIC-YYYYMM-8位随机HEX。
  4. 组装 Payload 并用 Ed25519 私钥生成签名，拼装成完整许可证字符串。
  5. 将记录写入数据库，初始状态 status = 'active'。

- 成功返回 (HTTP 200):
  {
      "ok": true,
      "license_id": "LIC-202609-1A2B3C4D",
      "license_key": "PPLIC-eyJjdXN0...Sfl8=",
      "plan_type": "planet",
      "max_servers": 5,
      "max_nodes": 12,
      "max_users": 12,
      "expire_at": 1758636000,
      "message": "生成成功"
  }

--------------------------------------------------------------------------------
5.3 吊销许可证接口
--------------------------------------------------------------------------------
- 请求路径: POST /api/v1/license/revoke
- 请求参数 (JSON):
  {
      "id": "LIC-202609-1A2B3C4D"              // 许可证唯一编号（或传入 license_key）
  }

- 服务端处理逻辑:
  将数据库中对应记录的 status 改为 "revoked"。

- 成功返回 (HTTP 200):
  {
      "ok": true,
      "message": "许可证已吊销"
  }

六、 数据库表结构建议 (SQLite / MySQL)
--------------------------------------------------------------------------------
以 SQLite 语法为例：

CREATE TABLE IF NOT EXISTS licenses (
    id TEXT PRIMARY KEY,                 -- 许可证唯一ID (如 LIC-202609-XXXX)
    customer TEXT,                       -- 客户名称/备注
    machine_id TEXT,                     -- 绑定的机器识别码
    plan_type TEXT,                      -- 套餐类型代码 (stardust/planet/star/galaxy/universe)
    max_servers INTEGER DEFAULT 1,       -- 服务器最大允许数
    max_nodes INTEGER DEFAULT 1,         -- 代理节点最大允许数
    max_users INTEGER DEFAULT 1,         -- 用户最大允许数
    issued_at INTEGER,                   -- 签发时间戳(秒)
    expire_at INTEGER,                   -- 过期时间戳(秒，0为永久)
    license_key TEXT,                    -- 完整卡密文本 (PPLIC-...)
    status TEXT DEFAULT 'active',        -- 状态: active(正常) / revoked(已吊销)
    last_ping_ip TEXT DEFAULT '',        -- 最后一次打卡的客户端IP
    last_ping_at INTEGER DEFAULT 0,      -- 最后一次打卡的时间戳(秒)
    note TEXT DEFAULT ''                 -- 额外备注
);

CREATE INDEX IF NOT EXISTS idx_lic_mid ON licenses(machine_id);
CREATE INDEX IF NOT EXISTS idx_lic_status ON licenses(status);
CREATE INDEX IF NOT EXISTS idx_lic_key ON licenses(license_key);

七、 Python 关键签名实现示例 (供参考)
--------------------------------------------------------------------------------
```python
import json
import base64
from cryptography.hazmat.primitives.asymmetric import ed25519

MASTER_PRIVATE_KEY_HEX = "875cf2bcc0c92bb602eb6c150693ed1e308321f803b7cbf3674ec028ebea0ff3"

def sign_license_payload(payload: dict) -> str:
    """输入 payload 字典，返回符合规格的 PPLIC- 许可证字符串"""
    # 1. 规范化紧凑排序 JSON
    payload_bytes = json.dumps(payload, sort_keys=True, separators=(',', ':')).encode("utf-8")
    
    # 2. Ed25519 私钥签名
    priv_bytes = bytes.fromhex(MASTER_PRIVATE_KEY_HEX)
    priv = ed25519.Ed25519PrivateKey.from_private_bytes(priv_bytes)
    sig_bytes = priv.sign(payload_bytes)
    
    # 3. Base64 URLSafe 编码并去除填充符 =
    payload_b64 = base64.urlsafe_b64encode(payload_bytes).decode("utf-8").rstrip("=")
    sig_b64 = base64.urlsafe_b64encode(sig_bytes).decode("utf-8").rstrip("=")
    
    return f"PPLIC-{payload_b64}.{sig_b64}"
```
