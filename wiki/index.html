📖 项目概述与系统架构

ProxyProbe 是一套专为代理服务器集群管理量身定制的一体化运维中枢，采用 Master-Agent（主控与分布式节点代理） 架构，彻底告别了传统面板依赖单机、协议流量统计不准、被控机故障难以快速定位等痛点。

全协议全覆盖

原生融合 Sing-box 与 Xray，深度支持 AnyTLS、Hysteria 2、TUIC v5、VLESS Reality、VMess、Trojan、Shadowsocks 等全量现代协议。

全链路会话级流量闭环

独创 Sing-box 跨行日志连接 ID (conn_id) 跨行会话追踪算法，解决短连接与并发下 AnyTLS / Hy2 流量无法精准归因到用户的业内难题。

VIP 等级物理隔离

细颗粒度控制节点访问权限、单节点限速与并发设备上限；低等级用户物理无感高等级专线，保障核心业务的高可用性。

TG 交互式双向运维 Bot

手机随时随地发送 /status、/test、/backup、/nodes 交互指令，自动秒级诊断全网节点并触发全量热备份推送。

架构设计思想
主控端（Master）统一维护配置数据库、用户凭证及聚合流量日志；被控节点（Agent）只作为无状态执行单元运行，断网时仍可依据本地缓存安全提供服务，重连后自动级联同步上传增量用量。

🚀 快速安装与部署指南

ProxyProbe 主控端已高度打包编译为跨平台原生二进制，配合 Caddy 自动申请免费 SSL 证书，5 分钟即可完成全栈部署。

1. 系统环境与前提依赖

推荐使用干净的 Linux 操作系统（Ubuntu 20.04+, Debian 11+, AlmaLinux 8+, Rocky Linux 9+）。主控机需开放 80、443 端口及业务代理端口。

2. 主控端一键部署

BASH 
# 从官方 Release 仓库拉取最新二进制并初始化主控端
mkdir -p /opt/monitor && cd /opt/monitor
curl -fsSL https://raw.githubusercontent.com/2290145679/ProxyProbe-Release/main/web-admin-dist.tar.gz -o web-admin-dist.tar.gz
curl -fsSL https://raw.githubusercontent.com/2290145679/ProxyProbe-Release/main/proxy-manager-linux-amd64 -o proxy-manager
chmod +x proxy-manager

# 解压前端面板资源
mkdir -p /opt/monitor/web-admin/dist
tar -xzf web-admin-dist.tar.gz -C /opt/monitor/web-admin/dist/

# 启动主控服务
./proxy-manager --port 28090

3. 配置 Caddy 域名与自动化 HTTPS

在 /etc/caddy/Caddyfile 中添加反向代理规则，Caddy 将自动申请并续签 Let's Encrypt / ZeroSSL 证书：

CADDYFILE 
tz.yourdomain.com {
    # 代理主控核心 API 与订阅生成
    handle /api/proxy/* {
        reverse_proxy 127.0.0.1:28090
    }
    handle /sub* {
        reverse_proxy 127.0.0.1:28090
    }

    # 客户端 Agent 自动化安装与同步脚本
    handle /proxy-agent.sh {
        reverse_proxy 127.0.0.1:28090
    }

    # 管理后台与用户控制台 SPA 单页应用
    redir /admin /admin/
    handle_path /admin* {
        root * /opt/monitor/web-admin/dist
        try_files {path} /index.html
        file_server
    }

    # 探针大盘前端与实时 WebSocket
    handle {
        reverse_proxy 127.0.0.1:28080
    }
}

4. 被控节点 (Agent) 挂载

在管理后台【服务器】添加一台新机器后，系统将自动生成唯一 Token 的单行 Shell 指令，在远端机粘贴回车即可完成 Agent 自动拉起与自愈守护：

BASH 
curl -fsSL https://tz.yourdomain.com/proxy-agent.sh | bash -s -- --token YOUR_SERVER_TOKEN

🌐 协议矩阵与多核心架构

ProxyProbe 深度整合了业界两大主流网络引擎：Sing-box (Go 现代核心) 与 Xray-core，并根据各协议的特性进行硬件级吞吐与伪装优化。

协议类型 驱动核心 关键特性 / 伪装层 推荐应用场景
AnyTLS Sing-box 自适应 TLS 指纹与动态握手混淆 对抗强封锁与敏感网络环境
Hysteria 2 Sing-box 基于 UDP/QUIC 的标准协议，拥塞控制强 跨国高丢包、高延迟长链路网络加速
TUIC v5 Sing-box 极轻量级 QUIC 传输协议，0-RTT 握手 移动设备抗切换与低延迟游戏加速
VLESS Reality Xray-core 借用真实大厂 TLS 证书（如 Yahoo / Apple），杜绝证书嗅探 主力直连节点、高隐蔽性日常冲浪
VMess / Trojan Xray-core 标准 WS+TLS / gRPC 伪装，老客户端兼容极佳 旧版客户端（小火箭 / Surge 早期版等）
Realm 级联中继 Realm Core 端口转发、中转落地机级联，流量自动同步 国内入口中转加速出口节点

📊 全协议双向流量归因与会话追踪引擎

在市面传统方案中，基于 Sing-box 运行的 AnyTLS、Hysteria 2 协议常常存在“只能测出在线设备数，无法将流量精确统计到具体用户”的短板。ProxyProbe 在 v2.5.21 中全面攻克了这一技术难题。

双行日志连接 ID (conn_id) 跨行会话追踪算法

Sing-box 的访问日志在连接生命周期中被拆分为两行异步事件：握手连接行（记录连接 ID 与源 IP:Port）与身份验证通过行（记录相同的连接 ID、用户凭据与目的域名）。

Session Correlation Parser 运作流程
1. 连接捕获阶段：监听 conn[xxxx] inbound/anytls: inbound connection from 1.2.3.4:5678，记录连接 ID 与源 IP 映射表并赋予 TTL。
2. 身份归因阶段：捕获后续 conn[xxxx] match[user_uuid]，通过 conn[xxxx] 建立源 IP:Port ➜ User ID 映射关系。
3. 流量级联阶段：通过 Clash API 抓取 socket 上下行数据流，精准沉淀至 proxy_traffic_hourly 及用户累计账单。

🚨 节点全景感知、智能诊断与巡检控制

为了让运维人员快速掌握全网健康状态，ProxyProbe 提供了全方位的感知矩阵与智能下钻诊断能力。

1. 健康度异常感叹号一键透视 (v2.5.22 新增)

当主控大盘检测到节点出现离线或握手超时，卡片顶部的健康度感叹号与 (X 个异常) 徽标支持直接点击交互，自动弹出诊断浮窗，直观列出所有故障节点名称、协议类型、归属服务器及具体报错日志，并支持一键发起即时重测。

2. 后台静默自动巡检周期自定义

支持在连通性矩阵界面通过下拉菜单调节后台巡检间隔（1 分钟、3 分钟、5 分钟、10 分钟、15 分钟、30 分钟、60 分钟），参数动态持久化并在后台线程自适应生效，告别固定写死的巡检周期。

3. 流媒体与主流 AI 平台解锁深度检测

支持对各大节点进行多平台流媒体及 AI 服务可用性探针（Netflix 原生、Disney+、YouTube Premium、OpenAI / ChatGPT、Anthropic Claude、Google Gemini），默认关闭以降低资源消耗，按需一键开启。

💎 VIP 等级套餐、物理隔离与配额控制

针对商业化运营，ProxyProbe 实现了节点与用户的多维度权限绑定与物理隔离机制：

  • 等级物理不可见：VIP1 用户获取订阅链接时，系统底层物理剥离 VIP2/VIP3 节点配置，杜绝抓包逆向越权。
  • 单节点限速与设备上限：支持在节点级别配置最高上行/下行速率限制，并在用户级别限制同时在线客户端 IP 数。
  • 全流程二次编辑 (v2.5.22)：已创建的 VIP 套餐支持完整数据回显、月/季/年付价格调整及流量配额二次更新。

❓ 常见问题排查 (FAQ)

Q: 如何检查 proxy-manager 运行状态与日志？

在 Linux 终端执行以下指令查看实时守护日志：

BASH
systemctl status proxy-manager.service --no-pager
journalctl -u proxy-manager.service -f

Q: 被控节点显示离线或无法连通？

1. 检查被控机防火墙是否放行了 Agent 端口与主控通信端口（默认通过 443 HTTPS 反向代理连接主控）；
2. 在被控节点执行 systemctl status proxy-agent.service 确认守护进程是否正常拉起；
3. 查看被控端日志 journalctl -u proxy-agent.service -n 50。
